## Turn 1 — `.cursorrules` 본문 작성 요청

### User

```
[P] 당신은 임베디드/셋탑 TV 도메인에 익숙한 시니어 C++ 엔지니어이며, TDD로 레거시·스켈레톤 코드를 확장·리팩토링하는 것을 전문으로 합니다.

[C] TDD_TV_Init 프로젝트(셋탑박스 리모컨 입력 → 채널 관리 → Tuner 연동)에서 Cursor AI가 항상 따라야 할 규칙을 프로젝트 루트의 `.cursorrules`로 작성하려고 합니다.
    - 저장소 구조: `include/`(헤더), `test/`(GTest), 루트 `CMakeLists.txt`
    - 기술 스택: C++17, CMake 3.14+, FetchContent로 Google Test/Google Mock v1.14.0, `gtest_discover_tests`
    - 도메인: 일반 채널 0~99, `remoteKey` enum, `TVController::pushButton(remoteKey)`
    - 외부(Tuner 업체) 제공: `include/Tuner.h`의 `Tuner` 인터페이스 — `seekCH()`, `setCH(const std::string&)`, `getCurrentCH()` (채널은 문자열)
    - 우리가 구현·테스트하는 대상: `TVController` 및 `remoteKey` 확장; Tuner 구현체 직접 작성·단위 테스트 금지
    - 요구사항 출처: `README.md`의 숫자/확인/선호채널/다음선호/채널검색/업·다운 동작 명세
    - 기존 테스트 스타일 참고: `test/TunerTest.cpp`의 `TEST_F`, `TEST_P`/`INSTANTIATE_TEST_SUITE_P`, `EXPECT_CALL`/`MOCK_METHOD`
    - `TVController.h`에 있는 `std::cout` 로그는 디버그용이며, 테스트 검증 대상이 아님

[T] 아래 요구를 만족하는 `.cursorrules` **전체 본문**을 작성해줘. (메타 설명·서두 말 없이 파일 내용만)

    1) 프로젝트·빌드
    2) 절대 규칙 (변경·위반 금지)
    3) TDD·구현 규칙
    4) 테스트 규칙
    5) 코드 스타일·구조
    6) AI 작업 시 금지·주의
    7) (선택) 커버리지

[F] 출력 형식
    - 마크다운 코드펜스 없이, `.cursorrules` 파일에 **그대로 붙여넣을 수 있는 평문**만 출력
    - 섹션은 `##` 제목 + 짧은 불릿 (한국어 위주, 식별자·API 이름은 영문 유지)
    - 분량: 80~150줄 내외
```

### Assistant

- `README.md`, `CMakeLists.txt`, `Tuner.h`, `TunerTest.cpp`, `TVController.h`, `remoteKey.h` 등을 읽고 교차 검토.

- 포함 내용: 프로젝트 개요, 빌드/ctest, Tuner 수정 금지, Red→Green→Refactor, GMock 규칙, README 6시나리오, AI 금지 사항.

**산출물**: 채팅 텍스트만 (아직 디스크 파일 없음)
