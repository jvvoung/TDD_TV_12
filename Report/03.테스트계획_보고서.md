## 1. 보고 목적

`docs/requirements_analysis.md`에는 **26개 acceptance 시나리오**(README 18 + 경계 8)와 비즈니스 규칙이 정의되어 있으나, TDD 실행을 위해서는 다음이 추가로 필요하다.

- **단위 테스트 범위**(In/Out of scope) 및 Mock vs Fake 역할 분리
- **테스트 ID**(`TC-*`)와 **시나리오 ID**(`1-1`, `A3` 등)의 **1:1 추적**
- **Fixture·Parameterized** 설계, **우선순위(P0/P1/P2)**, **Phase별 스프린트 계획**
- **커버리지 목표** 및 미결정 항목(E5, A8 등)의 **테스트 고정안**

본 보고서는 위 계획 수립 활동의 **요약·실행 로드맵**이며, 테스트 구현·`ctest` 운영 시 상세 내용은 `docs/test_plan.md`를 단일 실행 기준으로 사용한다.

| 구분 | In scope | Out of scope |

## 3. 계획 수립 방법

1. `docs/requirements_analysis.md` §1~§6, §4 경계(E1~E15)를 테스트 가능 단위로 분해
2. `test/TunerTest.cpp`의 Mock·`TEST_P` 패턴을 Controller 테스트에 **참고**(파일 수정 없음)
3. `test/TVControllerTest.cpp` 스켈레톤(`testFramework`)을 `TVControllerTest` Fixture 기반으로 전환 설계
4. 시나리오마다 **테스트 ID**, **우선순위**, **Given-When-Then**, **`EXPECT_CALL` 요약** 부여
5. TDD **Phase 0~6** 및 커버리지·리스크를 스프린트 단위로 정리

## 4. 테스트 전략 요약

### 4.1 Mock vs Fake

| 역할 | 도구 | 용도 |
|------|------|------|
| Controller 행위 검증 | **Mock** (`MockTunerForController`) | 호출 횟수·인자·순서 (`EXPECT_CALL`) |
| Tuner 계약 참고 | `TunerTest`의 Mock | 유효/무효 채널, `seekCH` until `""` 관례 |
| 선택 | FakeTuner | Mock 시퀀스 과다 시 `getCurrentCH` 일관성 |

**원칙**: Then은 Mock 기대로 표현; `favoriteChannels`·`searchResults`는 private이므로 **`setCH`/`seekCH` 간접 검증**.

### 4.2 우선순위 (P0 → P1 → P2)

| 우선순위 | README | 시나리오 ID | 목표 |
|----------|--------|-------------|------|
| **P0** | §1 숫자·확인 | 1-1 ~ 1-5, 1-4a/b | 버퍼·확정·선행 0·무효화 |
| **P0** | §5 업/다운(검색 없음) | 5-1 ~ 5-4 | ±1, 0↔99 래핑 |
| **P1** | §2·§3 선호 | 2-1, 2-2, 3-1, 3-2 | 토글·다음 선호·로테이션 |
| **P1** | §4 검색 | 4-1 | `seekCH` until `""` |
| **P1** | §6 업/다운(검색 있음) | 6-1 ~ 6-4 | `searchResults` 분기 |
| **P2** | 경계·모호 | A1 ~ A8, E1~E15 | 빈 OK, 재검색, 단일 목록 래핑 등 |

**사이클**: Red(테스트 1건) → Green(최소 구현) → Refactor → `ctest` 전체 Green.

## 5. 테스트 구조·Fixture

| 요소 | 제안 |
|------|------|
| 파일 | `test/TVControllerTest.cpp` 단일 확장 (500행 초과 시 분리 검토) |

| Parameterized | `TVControllerWrapChannelTest`, `DigitConfirm`, `InvalidChannel`, `SearchNavigate` |

**실행 명령**

```bash
cmake -B build && cmake --build build && ctest --test-dir build
```

## 8. 경계·예외 (핵심)

| 구분 | 대표 케이스 | 기대 |
|------|-------------|------|
| 채널 래핑 | 99+UP / 0+DOWN (검색 없음) | `setCH("0")` / `setCH("99")` |
| 숫자 | `0`,`7` / `9`,`9`,세 번째 | `"7"` / `99` 후 버퍼 `"9"` |
| 버퍼 무효화 | `4`,`5`,`6` 후 UP | `45`만 확정, `setCH` 추가 없음 |
| 선호 | NEXT_FAVORITE, 목록 없음 | `setCH` Times(0) |
| 검색 | `seekCH`→`""` 즉시 | 이후 ±1 모드 |
| 검색 네비 | `{4,6,14}`, 현재 `15` | UP→4, DOWN→14 |
| Controller 선검증 | 무효 버퍼 | `setCH` 미호출 |
| Tuner throw | invalid 채널 | **TunerTest** 전용, Controller와 분리 |

전체 16건 경계 표·9건 예외 표: `docs/test_plan.md` §4·§5.

## 10. 리스크·테스트 고정 결정

| 참조 | 이슈 | 테스트 고정안 |
|------|------|---------------|
| §2.1 | 1자리 vs 2자리 | 1자리=OK; 2자리=즉시 `setCH` |
| §2.4 | 미확정 버퍼 | 숫자·OK 외 모든 키 → 클리어 |
| E5 | 선호 1개, 현재=유일 값 | `setCH` 동일 채널 1회 |
| A8, E10 | 검색 `{6}` only, UP | `setCH("6")` Times(1) |
| E14 | 무효 `getCurrentCH` | no-op, `setCH` Times(0) |

**검증 한계**: private 상태는 `setCH` 순서·연속 키 입력으로만 간접 검증 → 필요 시 FakeTuner 도입(Phase 4+).
