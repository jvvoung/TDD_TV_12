## 3. Golden 대상 계층 (설계 결정)

| 계층 | 내용 | 채택 |
|------|------|------|
| **A (Primary)** | `RecordingTuner` 트랜스크립트: `setCH`, `getCurrentCH`, `seekCH` | **채택** |
| **B (Secondary)** | `std::cout` 리다이렉트 (`현재 설정하는 채널 : …`) | **미채택** |

**Layer A만 사용한 근거**

1. README/requirements와 1:1 대응이 명확함.
2. 로케일·공백·콘솔 인코딩 영향이 적음 (Windows CP949 콘솔 출력과 무관).
3. `.cursorrules`·요구사항 분석서에서 로그 검증을 Out of scope로 명시함.
4. GMock 테스트가 이미 Tuner API 계약을 검증하고 있음 — Golden은 **시나리오 통합 스냅샷**에 집중.

**트랜스크립트 한 줄 예**

```
setCH 12
getCurrentCH -> 6
seekCH -> 4
```

### 4.2 `RecordingTuner` 개요

- `seedChannel(ch)`: Given 현재 채널
- `seedSeekSequence({...})`: `seekCH` 반환 시퀀스 스텁
- `setRecording(bool)`: Given 구성·선호 등록 시 트랜스크립트 제외
- `beginRecordedAction()`: When 구간 시작 — **녹화 재활성화** + 트랜스크립트 클리어
- `transcript()`: 줄바꿈(`\n`) 연결 문자열

## 6. 실행·갱신 절차

### 6.1 일상 개발

```powershell
cmake -B build
cmake --build build --config Debug
ctest --test-dir build --output-on-failure
ctest --test-dir build -R GoldenMaster
ctest --test-dir build -L golden
```

> `GoldenMasterTest`는 `WORKING_DIRECTORY`가 **프로젝트 루트**(`CMAKE_SOURCE_DIR`)이므로 `test/golden/` 경로가 일관된다.

### 6.2 Golden 갱신 (의도적 동작 변경 시만)

```powershell
$env:UPDATE_GOLDEN="1"
.\build\Debug\GoldenMasterTest.exe --gtest_filter=GoldenMasterTest.*
Remove-Item Env:UPDATE_GOLDEN
```

PR에서는 `.golden` diff를 리뷰한다. **CI에서는 `UPDATE_GOLDEN` 사용 금지** (불일치 시 실패).

### 6.3 CMake / ctest 통합

```cmake
add_executable(GoldenMasterTest test/GoldenMasterTest.cpp)
target_link_libraries(GoldenMasterTest GTest::gtest_main GTest::gmock)

gtest_discover_tests(GoldenMasterTest
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
    PROPERTIES LABELS golden)
```
