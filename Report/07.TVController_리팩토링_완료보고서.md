## 4. Phase별 변경 상세

### 4.1 Phase 1 — 상수화

| 상수 | 값 | 용도 |
|------|-----|------|
| `MIN_CHANNEL` / `MAX_CHANNEL` | 0 / 99 | 기존 유지 (SSOT) |
| `MAX_DIGIT_BUFFER` | 2 | 2자리 입력 상한 |
| `SINGLE_DIGIT_LENGTH` | 1 | 1자리·OK 확인 분기 |
| `SEEK_LOOP_GUARD` | `MAX_CHANNEL + 1` | `runChannelSearch`의 `seekCH` 반복 상한 |
| `CHANNEL_ZERO` | `"0"` | 선행 0 처리 (`1-5`, `TC_1_5_ZeroSeven`) |

**효과**: `"0"`, `size()==1` 등 문자열·크기 리터럴 산재를 이름 있는 의도로 치환. **로직 변경 없음**.

### 4.2 Phase 2 — 중복 제거·의도 명확화

#### (1) `setTunerCh` — 이중 파싱 제거

| 구분 | 리팩토링 전 | 리팩토링 후 |
|------|-------------|-------------|
| 검증 | `normalizeChannelString` → `isValidChannelString` (파싱 2회) | `parseChannelValue` 1회 |
| 무효 입력 | `processingCH.clear()` 후 return | 동일 |
| 유효 입력 | `setCH(normalized)` + 버퍼 클리어 | 동일 |

제거된 private: `normalizeChannelString`, `isValidChannelString` (외부 미사용).

#### (2) `channelUp` / `channelDown` — 공통화

```
channelUp()  ──┐
               ├──► adjustChannelStep(±1)
channelDown() ─┘         │
                         ├─ searchResults.empty() → wrapChannel(current ± delta)
                         └─ else → findNext/PrevSearchChannel → tuneToChannelValue
```

- `tuneToChannelValue(int)`: `setTunerCh(std::to_string(channel))` 래핑
- **`searchResults.empty()` 단일 분기** 유지 (requirements §2.11)

#### (3) 숫자 버퍼 API 이름 정리

| 이전 | 이후 | 용도 |
|------|------|------|
| `clearBufferIfAny()` (반환값 무시) | `clearDigitBuffer()` | 선호·검색·다음선호 — 버퍼만 클리어 후 본 동작 |
| `clearBufferIfAny()` (true 시 return) | `discardDigitBufferIfNonEmpty()` | CH_UP/DOWN — 미확정 숫자만 버리고 **튜닝 생략** (`1-4b`) |

주석으로 CH_UP/DOWN early-return 의도를 코드에 명시.

### 4.3 Phase 3 — `handleDigit` 분해

| 헬퍼 | 역할 |
|------|------|
| `hasSingleDigitInBuffer()` | 1자리 대기 상태 |
| `hasLeadingZeroInBuffer()` | `"0"` + 다음 숫자 (`1-5`) |
| `startDigitEntry(digit)` | 빈 버퍼에 첫 숫자 |
| `appendSecondDigitAndConfirm(digit)` | 2자리 즉시 확정 (`1-2`) |
| `replaceLeadingZeroAndConfirm(digit)` | `0` 대체 후 확정 |
| `restartDigitEntry(digit)` | 2자리 이상 버퍼 시 새 숫자로 재시작 (`1-4a`의 `6` 등) |
| `handleConfirm()` | `hasSingleDigitInBuffer()` 시에만 `confirmBuffer()` (`1-1`, A7) |

**상태 전이 (요약)**

```
[empty] --digit--> [1자리]
[1자리] --digit, leading 0--> replaceLeadingZeroAndConfirm --> [empty]
[1자리] --digit, else--> appendSecondDigitAndConfirm --> [empty]
[2자리+] --digit--> restartDigitEntry --> [1자리]
```

## 5. 리팩토링 전·후 구조 비교

### 5.1 `pushButton` 흐름 (공개 API 동일)

```
pushButton(key)
  ├─ KEY_0..9     → handleDigit (내부 헬퍼로 분해됨, 동작 동일)
  ├─ KEY_OK       → handleConfirm
  ├─ KEY_FAVORITE → clearDigitBuffer + toggleFavorite
  ├─ KEY_NEXT_FAV → clearDigitBuffer + nextFavorite
  ├─ KEY_CH_SEARCH→ clearDigitBuffer + runChannelSearch
  ├─ KEY_CH_UP    → discardDigitBufferIfNonEmpty ? return : channelUp
  └─ KEY_CH_DOWN  → discardDigitBufferIfNonEmpty ? return : channelDown
```

| 버퍼 | `clearBufferIfAny`, `confirmBuffer` | + `clearDigitBuffer`, `discardDigitBufferIfNonEmpty` |
